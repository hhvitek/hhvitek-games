# Vítkovy hry

A collection of mobile games. A launcher (`index.html`) and separate games in `games/`.
Main target devices: Xiaomi 13T / 14T / 15T in portrait (CSS viewport about 393×873 to 412×915, about 393×760 with the browser bar).

## Before you finish a change to a game

1. `node tools/check.js <id>` passes (a hook runs it after every edit and again before you stop).
2. Run `tools/shots.js` for the changed games and **look at** `.playwright-mcp/sheet-<id>.png` (see Testing); the stop hook reminds you once when a changed game has no newer screenshots.
3. A new game or a bigger rebuild: follow the `new-game` skill, which ends with the `game-review` subagent.
4. What the user decided goes to "Decisions…" below; open questions to TODO.md.
5. A change the players will see gets a short Czech line under `## Nevydáno` in `CHANGELOG.md` (the stop hook reminds you). Never release by yourself: only when the user says so (see Deployment).

## Language

- **Code is English:** identifiers, comments, file and folder names, storage keys, commit messages. All generated code must be English.
- **`README.md` is Czech** and is for players and visitors only: what the games are, how to use them, images, contact, license. No developer or agent instructions there (adding a game, project structure, conventions): those belong in this file.
- **Everything the player sees is Czech** (labels, messages, help, settings, aria-labels).
- Exception: a game's folder (= its id and URL) is the game's Czech name without diacritics in kebab-case, e.g. `games/skladani-kostek/`, `games/pavouk/`, `games/soliter/`.
- Talk to the user in Czech.

## Contract between a game and the launcher

Games share no code or styles (exceptions: `images/`, for the card games `games/_cards/cards.js`, for the mariáš games `games/_cards/marias.js`, and for games with a computer opponent `games/_opponents/opponents.js`). The only links are these conventions:

1. **Folder and icon:** a game is `games/<id>/index.html` with `icon.svg` next to it. Add one line `{ id, name, description }` to `games/registry.js` (`name` and `description` are Czech, shown in the game's row).
2. **Home button:** the launcher opens a game as `games/<id>/index.html?menu`. The game has a `../../index.html` link (house icon) in its top bar, `hidden`, shown only with `?menu`:
   ```js
   if (/[?&]menu(=|&|$)/.test(location.search)) document.getElementById('btnHome').hidden = false;
   ```
3. **"Rozehráno" badge:** on every save the game sets `localStorage['games.<id>.inProgress'] = '1'` when it has an unfinished game, otherwise it removes the key.
4. **Play count:** the launcher increments `localStorage['games.<id>.plays']` when a game's row is tapped and sorts the rows by it (most played first; a game counts only once it was opened at least 5 times, below that it keeps its `registry.js` position). Games don't touch this key. The count is shown on the row only when "Ukazovat počet hraní" is on (`localStorage['games.launcher.settings']` = `{ showPlays }`, off by default). The order changes only on the next visit to the launcher, never under the finger.
5. **Offline mode and installation are handled only by the launcher.** A game registers no service worker or manifest.
6. **Storage key:** a game saves everything (settings, game, records) under `localStorage['games.<id>.state']`, next to the launcher's `games.<id>.*` keys. The launcher's "Smazat uložená data" removes exactly these keys of the registered games: `games.<id>.state`, `.inProgress`, `.plays`, `.mood`, `.treats` (Kočka's link, point 8), `hry.<id>.rozehrano` and the older `<id>.v1`, plus the launcher's own `games.launcher.settings` (GitHub Pages shares one origin between all of the user's projects). It keeps the launcher's `games.launcher.install` = `{ version, updated, first }` (when this version and the app first ran on the device, shown in Nastavení): that is not game data. Games that existed before the keys were renamed still read their older key once (`OLD_KEY`) and then remove it; their names that differ from the id are listed in `OTHER_KEY_NAMES` in `index.html`. Newer games (the template, Cesta ven, Zavři čísla) never had an older key and need no `OLD_KEY`.
7. **Error log:** the exact `/* ---------- Error log ---------- */` block from `games/_template/index.html` is the first `<script>` in every game and in `index.html`. It catches `error` and `unhandledrejection` and stores up to 50 entries (including repeated-error counts) in `localStorage['games.errors']`; a new error also copies the game's last saved `games.<id>.state` (up to 60 000 characters; only the newest 3 entries keep it, and it is dropped when storage is full) so the report lets you repeat it; storage failures are ignored. The block comes right after `<meta charset="utf-8">`, which stays the first thing in `<head>`. The launcher's `Hlášení chyb` screen renders the stored text escaped, shares a report only after the player taps `Poslat autorovi`: the whole report as a `.txt` attachment through the phone's share sheet (so nothing is cut), else as shared text, else a shortened `mailto:` that says so; no recipient is filled in (user's decision 2026-11-08), and its `Smazat seznam chyb` is the only action that removes this key. `Smazat uložená data` must keep `games.errors`. Opening any game or the launcher with `?testError` (e.g. `games/sudoku/index.html?testError`) throws one test error, to try the whole flow.
8. **The Kočka link** (user's decision 2026-11-12: switchable in the launcher's Nastavení, **off by default**, `games.launcher.settings.catLink`, checked): Kočka writes `games.kocka.mood` = `{ name, mood, wants, ill }` on every save; when the link is on, the launcher shows a line under the header (Koxa's icon, name and how she is; a tap opens Kočka) and every *other* game started from the launcher adds one treat to `games.kocka.treats` = `{ n, day, taken }` (at most 5 a day counting `n + taken`, a new day starts over); Kočka moves `n` into her pamlsky when it opens and adds it to `taken`. Other games do not change. This is the only data shared between games.

## Adding a game

Follow the `new-game` skill (`.claude/skills/new-game/SKILL.md`): it copies `games/_template/`, adds the icon, the
`games/registry.js` line (its position is where the game's row appears until the game is played 5 times) and the README row,
says which game to copy each pattern from, adds the game to `tools/shots.js`, and ends with screenshots and the
`game-review` subagent. `sw.js` picks the game up from `registry.js` by itself; players get it with the next release
(a new game is a `minor` release only when the user asks for it, see Versioning). Add its line to `CHANGELOG.md`.

## Shared images (`images/`)

- `images/sets.js` defines `globalThis.IMAGE_SETS = { <set>: { name, kind: 'photo'|'coat'|'drawing', items: [...] } }`. A `photo` fills its tile (`cover`); a `coat` or `drawing` is shown whole on a white tile. An item is `{ file, name, author, license, source, group? }`: `file` is relative to `images/`, `name` is Czech (may be shown to the player), `group` is an optional set of items that belong together.
- Sets: `cats` (cat photos), `nachod` (castles and places of the Náchod district + major sights of the Hradec Králové region), `coats` (coats of arms of the Náchod district municipalities + district towns of the region), and the drawn `mushrooms`, `birds`, `produce` (fruit and vegetables). Each has 42 items: 34 regular + 2 groups of 4. Index 0 of `nachod` and `coats` is Náchod. Spojování čísel uses the first 17 items of a set, so they are the most distinct ones.
- A game that uses the sets lists them itself (Mahjong and Spojování obrázků `SETS`, Spoj tři `SYMBOLS`; Spojování čísel takes every set): a new set is added there too.
- A game loads them with `<script src="../../images/sets.js"></script>` and uses `../../images/<file>`. Without `images/` the game must still work (image options just disappear).
- Photos and coats come from Wikimedia Commons under free licenses (CC BY, CC BY-SA, CC0, public domain). A game that shows them must list authors and licenses (e.g. a "Autoři obrázků" screen).
- Drawings are hand-written SVG made for this project (CC0, `author` = the project, `source` = the repository): viewBox 0 0 100 100, transparent background, dark brown outline `#2e2118`, flat colours, recognisable on a 44×58 px Mahjong tile. The credits list only their names.
- The project is deployed and copied as the whole folder structure (a game is no longer a single standalone file).

## Rules for every game

- **One HTML file per game:** HTML + CSS + JS inline, no external libraries or fonts. The only shared files allowed are those in `images/` and, for the card games (Solitér, FreeCell, Pyramida, Pavouk, Oko bere, Oko bere plus mínus, Prší), `games/_cards/cards.js` (loaded after `images/sets.js`; a change there affects all of them, test them all; Oko bere and Prší use only its tables, backs and faces; their mariáš cards come from `games/_cards/marias.js`, loaded after `cards.js`: a change there affects both, test both), and for the games with a computer opponent (Kostky, Dáma, Piškvorky, Oko bere, Oko bere plus mínus, Prší) `games/_opponents/opponents.js` (loaded after `cards.js`; a change there affects all of them, test them all). It must work when opened from disk (`file://`).
- **Own look:** each game has its own styles and themes as it needs (contrast differs between games).
- **Game name in the top bar:** a visible `<h1>` with the game's Czech name between "Nová hra" and the "?"/settings buttons (it may wrap to two lines when the home button is shown). Scores or other info go on their own row below the bar, not in place of the name.
- **No senior constraints** (user's decision 2026-11-12): the games used to follow strict rules for a senior player
  (touch targets ≥ 0.8 cm, text ≥ 18 px, no time pressure, no long presses or hidden gestures, nothing "advanced" on
  the game screen, a dashed "dimmed" look for every unavailable action, Zpět everywhere). Those rules are gone: a game
  may use any controls (swipes, long presses, multi-touch, drag, tilt), time pressure, smaller text and targets and
  advanced options, as fits the game. Existing games keep how they work until they are changed on purpose.
- **Behaviour every game keeps:**
  - Czech, informal "ty", gender-neutral where it talks about the player (not "uhodla jsi"),
  - help behind the "?" button; settings on their own screen, applied at once (a change that needs a new game starts it after returning to the game and says so),
  - an **Undo** button ("Zpět") where the game wants one (not required),
  - settings and the game in progress are saved to `localStorage` under the game's own key (`games.<id>.state`), all in `try/catch`, and survive closing and restarts; corrupted or invalid data must never crash the game (fall back to defaults),
  - on start the game asks for persistent storage so the browser doesn't delete data by itself: `navigator.storage.persist()` (in `try/catch`; the launcher does it too),
  - starting a new game in the middle of one asks for confirmation,
  - the phone's Back (gesture or button) closes the topmost screen or dialog, like its own Zpět, instead of leaving the game: copy the "Back button" block from any game. It works because every layer (`#screenSettings`, `#screenHelp`, `#screenCredits`, `#modal`) is shown and hidden only through its `hidden` attribute and every screen has a `[data-act="close"]` button.
- **Themes:** a solid colour (or a subtle texture), no colour bands. All elements of the game screen including details and the toast follow the theme, no exceptions in other colours.
Every game also offers the theme "Papír" (`id: 'paper'`, meta `#f4ebdf`; the card games as the paper table in `games/_cards/cards.js`) with exactly the launcher's colours: background `#f4ebdf`, ink `#2b1a0e`, soft text `#6f5a48`, lines `#e6d8c6`, buttons `#7a4520` / `#fff` / shadow `#3f220e` (checked). It is an option, not the default (Sudoku, Skládání kostek, Přelévání, Hanojské věže, Pexeso, Kostky, Oko bere, Oko bere plus mínus and Prší start in it). A renamed theme id is mapped to the new one when the settings load (e.g. `cream` → `paper`).
  Settings, help and dialogs are the exception (user's decision): one light look, the same in every game and in the launcher, whatever the game theme. Copy the `.paper{...}` rule from the template exactly (`node tools/check.js` compares it); paper elements use only its `--p*` colours.
- **Layout:** `#app` is as tall as the visible window: `height:var(--app-h,100dvh)`, where `--app-h` is `visualViewport.height` measured by the "Visible height" block from the template (checked), plus `env(safe-area-inset-*)` padding; the viewport meta is `width=device-width, initial-scale=1` without `viewport-fit=cover` (checked), the board size is computed from the available space so it fits without scrolling in the default settings.
- **Portrait only:** the games are made for a phone held upright. The installed app is locked to portrait (`"orientation": "portrait"` in `manifest.webmanifest`); in a browser tab a phone turned sideways (`orientation:landscape` and height up to 500 px) shows the notice "Otoč telefon na výšku" over the game (copy the `#rotate` block from the template, checked). Tablets and computers are not affected.
- **One side margin:** the top-bar buttons, the board and the bottom buttons start 12 px (about 0.3 cm) from the left and right edges (plus `env(safe-area-inset-left/right)`), so they line up; nothing on the game screen is closer to the side. The board also keeps at least 12 px from the top bar (or the score row) and from the hint text / bottom controls, at every window size (a small phone 360×640, a short wide browser window 745×527 or 1024×768): when the window is short the board shrinks, it never overlaps, gets cut or scrolls. The title in the top bar is always whole: at 360 px it may wrap between words, never inside a word. `tools/shots.js` measures all of this and lists games that differ.
- **When talking to the user, give sizes in centimetres or percent of screen width, not pixels.**

## Decisions for the whole project

The user chose these; keep them:
- **Settings, help and dialogs** have one light look in every game and in the launcher, not the game theme (see Themes).
- **Game title font:** the `<h1>` in a game's top bar uses the system font (`system-ui`, Roboto on Android) at weight 800, not a serif (Georgia does not exist on Android). The paper screens keep their Georgia headings.
- **App name:** "Vítkovy hry" (manifest `name` and `short_name`, the launcher's `<title>` and its Nastavení heading, README).
- **App icon:** a scene after the user's "Vítkovy hry" poster and colours: Náchod castle on a hill (round tower rising from the roof, a dark turret, two rows of windows), the user's black tortoiseshell cat (yellow-green eyes, ginger patches and blaze) in front, leaves and the orange die in the top left corner; no text (the home screen shows the name below it). The previous icon, a tilted orange die on black-aubergine, is commit 7d2c260.
- **Launcher:** one column of rows (icon, name, description, "Rozehráno" next to the name), today's weekday and date as the header with the app icon on the right, as tall as the two lines; the play count is hidden by default and can be turned on in the launcher's Nastavení ("Ukazovat počet hraní").
- **Offline mode:** every file comes from the cache at once; a new version is looked for in the background whenever the app is opened and is downloaded whole, only when a new one was released, then shows on the next opening (see Deployment). An interrupted download keeps the old version whole. "Smazat uložená data" removes the games' saved data, not the offline cache.
- **Versioning:** SemVer starting at `1.0.0`. A release is the sum of the commits since the previous tag and happens only when the user asks ("vydej"): patch by default (`1.0.1`), `minor` (`1.1.0`) or `major` (`2.0.0`) only when the user says so. Branches are optional and named after their content, never after a version. Only a release tag is deployed; a push to master deploys nothing. The launcher's Nastavení has the card "Verze aplikace": the version, "Vydáno", "Aktualizováno v tomto zařízení", "Poprvé spuštěno v tomto zařízení", "Co je nového" (the whole history: every release from `CHANGELOG.md`, newest first, in a scrolling dialog; user's decision 2026-11-08, before the latest 3; never opens by itself) and "Zkontrolovat aktualizace" (with "Načíst novou verzi" when one was downloaded).
- **Error reports** (user's decision 2026-11-08): the launcher's Nastavení always shows the "Hlášení chyb" card, and its screen keeps the table of errors and the "Uložit jako soubor" button. A report is sent whole, as an attachment, never cut.
- **Supply chain** (user's decision after the npm attacks of 2025): the players get only our own code: no CDN, no npm packages, no external scripts or fonts in the games or the launcher; the tools use only Node's built-in modules (no `package.json`). Third-party code is pinned, never `@latest` or a moving tag, and updated only to a release that has been out for at least 7 days (bad releases are usually caught within hours or days; user's decision 2026-11-08, before 14 days): GitHub Actions by full commit SHA with the version in a comment (checked by `tools/check.js`; look inside a composite action that its own `uses:` are pinned too). Exception: the Playwright MCP in `.mcp.json` runs `@latest` (user's decision 2026-11-11, see Playwright). The 7 days are only for code we take from others: our own releases go out at once.

## Decisions for single games

The user chose these; keep them when changing a game:
- **Logik:** the default control is dragging ("Přetahování prstem", `mode: 'drag'`), and the "Ovládání" section is the first one in its settings.
  The layout follows the old Logik the player knows: no row numbers, the black/white feedback on the left of each row, Vzdát se (flag), Zpět and Zkontrolovat (tick; round arrows = Nová hra after the end) in a column on the right as pictures only, without labels (a deliberate exception: the player learns them; the help shows them). The column follows the rows (`alignSide()`): the flag is one row high next to the secret code, Zpět one row high, one free row, then Zkontrolovat over the two bottom rows. The secret code is a row of dark covers with a question mark; a tap on it does the same as the flag. The status line ("Přetáhni barvy do jamek" etc.) is off by default and turned on in settings ("Řádek s nápovědou", `hints`); without it the bottom tray holds only the colours, and with the colours on the right there is no tray. The default theme is "Klasika" (`theme: 'classic'`) (it replaced "Javor"; older saves still holding an old default, Tmavé dřevo or Javor, switch to it once, `look: 2` marks a save that knows), a soft natural light grey with flat light holes, a thin outline and hardly any shadows, like the old game on a computer screen (the blue in the old photo was the camera; plain white was too harsh); a colour fills its hole up to the outline, and in the feedback an empty place is a small grey dot so the white peg (white, dark outline) is unmistakable; the row to play has a quiet grey frame, not a blue one. The colours are by default in the bottom tray, lined up with the columns of holes and all with the same spacing as the holes (`alignPalette()`: with 6 colours and 4 holes the middle four sit under the holes and one more on each side); the holes sit in the middle of the screen (slightly smaller holes are fine for that), so the colours have equal margins on both sides (wider than 12 px: a deliberate exception). Where the holes are too close (e.g. 360 px wide) the colours are spread evenly from margin to margin. The secret-code box hugs the covers only, and the flag is centred next to it; "Barvy ve sloupci vpravo" (`palRight`) moves them into the right column: Zpět right above Zkontrolovat (no free row), the colours at the bottom of the column with one free row above Zpět, as big as the holes and close together, not one per row; smaller only when they do not fit (two columns when one would be under 44 px). The first six colours keep this order: červená, bílá, zelená, černá, modrá, žlutá.
- **Sudoku:** "Stejná čísla" (`hlSame`) and "Kolik kterého čísla zbývá" (`counter`) are on by default (user's decision 2026-11-11); older saves switch them on once (`aids: 1` marks a save that knows), after that a player who turns them off keeps them off. Pencil notes are drawn large (`.36` of the cell in fixed rows of a third, `minmax(0,1fr)`, so 7 8 9 are never cut; more when the cell has few notes in "Větší, vedle sebe").
- **Skládání kostek:** the default theme is "Papír" (`theme: 'paper'`).
- **Padající tvary:** the default theme is "Dřevo" (`theme: 'wood'`); by default the shapes fall by themselves "Pomalu" (`speed: 'slow'`) with "Postupně zrychlovat" on (`accel: true`). The Pauza button and "Jen tlačítkem" in settings stay.
- **Mahjong:** the default theme is "Dřevo" (`theme: 'wood'`).
- **Spojování obrázků** (Shisen-Sho, user's decisions 2026-11-12): named so it is not confused with Spojování čísel, its row right after Mahjong in `registry.js`. A flat full rectangle of tiles (Malý 6 × 8, Střední 7 × 10 default, Velký 8 × 12 with the two framed groups); a pair goes when a line with at most two bends joins it through empty cells or round the edge. Tiles, picture sets, themes (default "Dřevo") and credits are copied from Mahjong. Every deal can be finished: the faces are shuffled until the game's own solver finishes the board (also for Zamíchat, randomness from `G.seed`). ## Visible height (user's decision 2026-11-08: one rule for every browser, never a fix for one phone or browser)

The user reported that in the app installed by **Brave** on a Samsung S25 the bottom buttons of nearly every game were
cut off and could not be scrolled to; in the browser, and in the app installed by **Chrome**, everything fit. A
temporary "Údaje o obrazovce" card in the launcher's Nastavení (1.0.3) measured the same screen (360 × 780, dpr 3,
731 px visible between the status bar and the gesture bar):

| | visible | `100dvh` | safe area bottom | `visualViewport` | `clientHeight` |
|---|---|---|---|---|---|
| Chrome, browser tab | 674 | 675 | 0 | 675 | 674 |
| Chrome, installed app (`standalone`) | 731 | 731 | 0 | 731 | 730 |
| Brave, its "installed app" (reports `display-mode: browser`) | 731 | 746 | 15 | 746 | 674 |

and the earlier screenshot of Logik in the Brave app looked laid out about 780 px tall. So browsers disagree: Brave
counts the bars into its viewport (and its fixed layers end at 674). Removing `viewport-fit=cover` (1.0.2) did not help.

The rule since then (1.0.4): every game sizes `#app` from `visualViewport.height` (times its scale) instead of trusting
`100dvh`, measured on every resize, on `pageshow` and 0.1 / 0.5 / 1.5 s after loading, and a changed height dispatches a
`resize` so the game lays itself out again. The `env(safe-area-inset-bottom)` padding of `#app` stays. `100dvh` is
only the fallback before the script runs. Nothing detects a phone or a browser. Whether this alone fixes Brave was
not known when it was written: the games also store what they measured in `games.launcher.diag`, shown in the
temporary card, to be checked on the phone; remove both TEMPORARY parts (the card in `index.html`, the
`games.launcher.diag` write in every game and the template) once it is confirmed.

## Patterns every game follows

These came out of the reviews; new games must keep them. `games/_template/` shows the basic ones, the `new-game` skill
names a game to copy each of the others from, and `tools/check.js` checks those marked (checked):
- **Saved data is checked on load:** only known settings are taken over (whitelist of `DEFAULTS` keys, checked), every history entry is validated (a broken history only loses Undo), and the end of the game is derived from the board, not trusted from the save.
- **Records per variant:** `bests[rulesKey(rules)]`, where the key has every rule that changes difficulty. Each history entry stores the record before the move (`bb`), and Undo puts it back, so a record cannot be inflated by playing and undoing. Rules that change difficulty belong to the game (`G.rules`, or e.g. `G.draw`, `G.passes`): a change in settings applies from the next game and says so. Zavři čísla keeps statistics instead of a record: each game counts once, at its first end (`G.counted`); Undo after the end does not take it back. The card games keep played/won statistics per variant too (Pavouk by suits, Solitér by draw and deal, Pyramida by passes and deal).
- **Randomness after a move comes from `G.seed`** (saved with the game and with every history entry), so Undo and the same move again give the same pieces, stones, tiles or dice (Spoj tři, Skládání kostek, Padající tvary, Zavři čísla, Spojování čísel).
- **End dialogs belong to their game and never open over Settings or Help** (checked): a delayed "won"/"stuck" dialog goes through `whenFree(g0, ms, fn)` from the template, which waits until no dialog, Settings or Help is open and drops the dialog when another game started meanwhile; `fn` checks anything else (e.g. nothing `busy`).
- **A settings change that needs a new game says so also after a finished game** (checked): the notice in Settings and the toast after returning use `!isFresh()`, not "a game in progress" (a lost game can still be revived by Undo). Only the extra words "a rozehraná hra se ztratí" belong to a game in progress. Settings are saved at every tap, so the app may be closed while Settings are open: on the next start a saved game whose rules differ from the settings is handled as closing Settings would (template, section Start). A rule that applies "from the next game" (card games: draw, passes, deal, suits) replaces an untouched deal at once, and its notice says "Rozehraná hra zůstává" only while a game is in progress.
- **Sizes inside pieces come from a size variable** (checked): `padding`/`margin` in `%` is taken from the parent's width, not from the element (the tiny dice pips of Zavři čísla); use `calc(var(--size) * x)`.
- **The toast never covers the score row:** it sits at the bottom above the controls (template), or a game with the toast at the top moves it just below its score row in `toast()` (e.g. Spoj tři).
- **Opening Settings or Help hides the toast** (checked), and every game has the test hook `window.<Name> = { …, get state() }` (checked).
- **While something is running** (`busy`: generating, a cascade, a deal animation), a tap explains itself with a short toast ("Chvilku, …") instead of doing nothing; a second "Nová hra" is ignored.
- **Taps on the hinted card** do the move the hint showed.
- **Computer opponents come from `games/_opponents/opponents.js`** (checked: a game that uses `OPPONENTS` loads it). The game keeps its own AI and defines its levels `LEVELS = [{ id?, title, desc }]` from the weakest to the strongest; the module gives everything else, so the opponent looks the same in every game: `O.create(rnd, avoidNames, avoidFaces)` draws a new `{ name, fem, face }` at every new game or match (never the previous name; at one table different names and faces), `O.valid` checks a saved one (an invalid one is replaced, the game goes on), `O.head(foe, { mood, badge })` draws the avatar, the name and a badge: `O.levelBadge(LEVELS, i)` (stars counted by the game's own levels: ★☆ ★★ or ★☆☆ … ★★★) or `O.traitBadge(text)` for a play style (Prší). `O.levelName(LEVELS, i)` ("Zkušený hráč ★★☆") is used in settings, help and dialogs, `O.past(foe, 'vyhrál', 'vyhrála')` for the past tense, moods `calm | happy | sad | think` (thinking while it plays, happy/sad at the end of a round). Sizes and colours come from the game's `--op-ava`, `--op-ava-bg`, `--op-name`, `--op-accent`. Texts on the game screen use the opponent's name ("Bod má Jarka"); settings and help say "soupeř" and that the name changes every game. Copy the use from Kostky (a big panel) or Oko bere (a small head).

## Deployment

GitHub Pages, deployed by GitHub Actions (`.github/workflows/deploy.yml`) only from a release tag `vX.Y.Z`; Settings → Pages → Source is "GitHub Actions" and the `github-pages` environment allows tags `v*`. A push to master stores the code on GitHub and deploys nothing. On the phone open the URL in Chrome → ⋮ → "Přidat na plochu".

**Releasing** (only when the user asks, e.g. "vydej", "vydej minor"):
1. Everything is committed on master (merge a branch first). `## Nevydáno` in `CHANGELOG.md` says in plain Czech what the players get since the last release; fill it in from `git log <last tag>..` if lines are missing, and commit.
2. `node tools/release.js [patch|minor|major] --trailer "Co-Authored-By: …"` (your attribution line; `--dry-run` first to show the user the version and the lines). It checks master is clean and not behind, `tools/check.js` passes, `Nevydáno` is not empty and something for the players changed; then turns `Nevydáno` into `## X.Y.Z – <date>`, writes `version.js`, commits `Release X.Y.Z`, tags `vX.Y.Z` and pushes both (`git push --atomic origin master vX.Y.Z`).
3. The tag starts the workflow: `tools/release.js --verify` (tag = `version.js`, CHANGELOG section, tag on master), `tools/check.js`, then the site without `tools/`, `docs/`, `.claude/`, `.mcp.json`, `games/_template/` and `*.md` goes to Pages. Watch it in the repository's Actions tab.
To bring an older version back: Actions → Deploy → "Run workflow" on its tag. Never edit `version.js` by hand and never move a tag.

**Updates on the device:** `sw.js` imports `version.js`, so every release is a new service worker (the launcher registers it with `updateViaCache: 'none'`, so the browser asks the server on every opening; the answer is tiny when nothing changed). The new worker downloads every app file and the photos into its own cache `hhvitek-games-<version>` and takes over only when every app file arrived (`skipWaiting`, `clients.claim`); then the old cache is deleted. Until then, and offline, everything comes from the old cache at once (every file is cached once, without `?menu`). The open launcher keeps showing the old version until it is opened again, or "Načíst novou verzi" in Nastavení. The file list comes from `games/registry.js` and `images/sets.js` (plus the shared scripts); files no longer listed leave the cache.
